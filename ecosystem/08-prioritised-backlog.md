## How to read an item

| Field | Meaning |
| --- | --- |
| **ID** | `INI` initiative · `EPC` epic · `FEA` feature · `ENA` technical enabler · `MIG` migration · `TST` test · `DOC` documentation · `OPS` operational task |
| **Description** | What is built or changed, concretely |
| **User or operator value** | Who benefits, and how |
| **Repositories affected** | Real repository names from [03-repository-responsibilities.md](03-repository-responsibilities.md); today's names where the work happens before a split |
| **Dependencies** | Other item IDs that must complete first, or `none` |
| **Acceptance criteria** | Testable and falsifiable. If a criterion cannot fail, it is not a criterion |
| **Test requirements** | The kind of test that proves it, not a wish for coverage |
| **Priority** | `P0` the platform cannot safely operate without it · `P1` required for the ecosystem experience · `P2` important expansion · `P3` optional or future |
| **Complexity** | `XS` under a day · `S` a few days · `M` one to two weeks · `L` three to six weeks · `XL` six weeks or more |
| **Suggested phase** | `P0`–`P13` from [06-ecosystem-workflow.md](06-ecosystem-workflow.md) |
| **Blocking status** | What cannot proceed until this lands, or `blocks nothing` |

Priority and phase are independent axes. A `P0` item in `P13` is one the platform cannot
safely operate without, which cannot be built until `P13`'s dependencies exist — restore
drills are the archetype.

## 4. Technical enablers

Infrastructure, libraries and platform work. **ENA-01 to ENA-12 are the twelve Phase 1
correctness fixes** from [06-ecosystem-workflow.md](06-ecosystem-workflow.md), kept contiguous
and in the order they appear there so they can be picked off as a set. They are enablers rather
than features because each is a correctness change to the money path, not a new capability.

#### ENA-01 · Deterministic settlement id and a unique index on `fee_settlements`

- **Description** — Derive the settlement id from `(bot_id, period)` instead of `randomUUID()` (`crucible/services/crucible/src/store.ts`), and add a unique index on `fee_settlements (bot_id, period)` in `crucible/services/crucible/src/migrate.ts`.
- **User or operator value** — Traders stop being double-billed performance fees. Pay correctly honours two different idempotency keys today, so the defect is Crucible's alone.
- **Repositories affected** — `crucible`
- **Dependencies** — EPC-01
- **Acceptance criteria**
  - The Pay idempotency key for a given `(bot_id, period)` is byte-identical across retries.
  - A second settlement insert for the same `(bot_id, period)` raises a unique violation.
  - A retried settlement returns Pay's replayed response, not a second charge.
- **Test requirements** — A two-worker concurrency test that runs the hourly sweep twice against one Postgres and asserts exactly one charge.
- **Priority** P0 · **Complexity** S · **Suggested phase** P1 · **Retires** part of TD-01's cost

## 13. Where this backlog disagrees with source

Recorded rather than silently resolved, because [00-current-state.md](00-current-state.md) is
the baseline every other document rests on and a correction there is worth more than a
consistent backlog.

**`assignHomestead` may already be conditional.** [00-current-state.md](00-current-state.md)
§3.2 records a lost update: "`UPDATE tiles SET owner_id` with no `WHERE owner_id IS NULL`", and
[06-ecosystem-workflow.md](06-ecosystem-workflow.md) Phase 1 item 7 is "`assignHomestead` gets
`WHERE owner_id IS NULL`". Current source at
`ninety-days-after/services/game/src/world/generate.ts` performs the update inside
`claimFirstFree` with `.where(and(eq(tiles.id, candidate.id), isNull(tiles.ownerId)))` and
returns the claimed row, which is the conditional claim the fix describes. Either the audit
predates commit `4b4c537`/`ee0250e`, or the defect lives on a different path — the surrounding
comment names a second failure mode, a tile left marked `homestead` and owned by a player that
was never created.

ENA-07 is therefore written as *prove and guard* rather than *add the clause*: the acceptance
criteria assert the conditional claim, the retry behaviour and the atomicity of the tile update
with the player insert, and the concurrency test is the deliverable either way. **The audit
should be re-run against this path before ENA-07 is scheduled**, and §3.2 corrected if the fix
has already landed.

Nothing else in this backlog contradicts the spine. Where a phase document and an architecture
decision could be read two ways — the scope of Phase 1 item 5, and whether the ledger relay
ships in P2 or P6 — this document takes the narrower reading stated in
[06-ecosystem-workflow.md](06-ecosystem-workflow.md): ENA-05 is refuse-or-refund only, with
provisioning deferred to FEA-33 in P10, and ENA-26 defines the envelope in P2 and ships the
relay in P6.
